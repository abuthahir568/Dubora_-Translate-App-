# DUBORA AI — Architecture & Platform Integration Guide

## 1. Implemented Android Capabilities (Live in This Build)
- **Media Playback Engine**: Jetpack Media3 `ExoPlayer` (`1.11.1`) supporting local MP4, MOV, MKV, M4V, and WebM files selected via Android's zero-permission Storage Access Framework (`ActivityResultContracts.OpenDocument`).
- **Audio Chunk Extraction**: `AndroidAudioExtractor` (`MediaBridge`) decodes audio windows (`[windowStartMs, windowEndMs]`) via `MediaExtractor` + `MediaCodec` (with a 12s per-window decode deadline), downsamples to 16 kHz mono PCM16, computes RMS audio energy to skip silent windows without calling the API, and packages WAV payloads under 20 MB.
- **Gemini AI Speech Recognition, Diarization & Translation**: `GeminiDubbingEngine` defaults to `gemini-3.5-flash-lite` (Fast Stream) for low-latency, high-throughput dubbing on both short clips and 3-hour movies, and supports `gemini-3.8-flash` (Cinema Balanced / Studio Nuance) via **Firebase AI Logic** (`Firebase.ai`, attested with Firebase App Check — no client-side API key needed). If `gemini-3.8-flash` encounters quota exhaustion, `429` rate limits, or `503` high demand, the engine automatically fails over to `gemini-3.5-flash-lite` cleanly. Temporary `503`/`429` bursts retry up to 3 times with exponential backoff (respecting server `retry in Xs` hints), while configuration/App Check errors are checked separately.
- **Voice Generation**: `AndroidTtsVoiceEngine` (`VoiceGenerationEngine`) synthesizes speaker-matched `.wav` dialogue cues on device via `TextToSpeech.synthesizeToFile(...)` with per-speaker pitch/rate offsets, voice style modulation, and gentle adaptive rate fitting for dialogue timing.
- **Audio Mixing & Ducking**: `DubbingPlaybackCoordinator` tracks ExoPlayer's playback clock with `O(log n)` cue lookup and seek-anywhere window scheduling (`12s` initial startup slice -> configurable `12s–30s` rolling windows capped at a 2-window lookahead), plays synchronized dubbed `.wav` cues, and dynamically ducks ExoPlayer's original audio volume (`0.16f`) during AI speech while preserving background music and SFX between lines.
- **Local Persistence**: Room (`DuboraDatabase`) stores imported movie metadata, extracted video frame thumbnails, playback positions, and offline cached dub segments (`Downloads` tab). DataStore (`UserPreferencesDataStore`) persists subtitle styling, voice profile, ducking, and network preferences.
- **Cloud Sync & Auth**: Google Sign-In via Jetpack `CredentialManager` (`GetSignInWithGoogleOption`) + Cloud Firestore (`/users/{uid}` and `/users/{uid}/dubbing_sessions/{sessionId}`) secured by hardened `firestore.rules`. Movie video files remain strictly on device and are never uploaded.

## 2. Capability & Platform Gaps / Next Integration Phases
- **Voice Stem Separation (Demucs / Spleeter)**: Currently uses real-time original-audio ducking (`Preserve Background Music` mode) rather than neural vocal/BGM stem isolation. Full vocal removal requires an external GPU stem-separation microservice or an on-device ONNX/TFLite Demucs model.
- **iOS AVPlayer / Capacitor Parity**: The `MediaBridge` interface (`DubbingInterfaces.kt`) defines the contract (`extractAudioChunk`, `PlatformBridgeStatus`) for an iOS `AVPlayer` + `AVAssetReader` native Swift plugin when packaging a cross-platform Capacitor shell.
- **Gemini Live Bidirectional WebSocket Streaming**: Firebase AI Logic unary multimodal audio chunking (`generateContent`) is active with a configurable seek-aware lookahead window (`12s–30s`). Upgrading to a dedicated Node.js + WebSocket relay for sub-second streaming or cloud Gemini TTS audio bytes can plug directly into `TranslationEngine` and `VoiceGenerationEngine`.
